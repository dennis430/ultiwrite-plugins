# Ultiwrite distribution preparation

The canonical message is **Asymmetric Diligence & Investigative Intelligence**: start with supplied evidence, investigate outward, expand the evidentiary foundation, then reconcile the wider picture. Catalog fields distinguish the hosted platform's capabilities from what each connector actually exposes.

`catalog.json` owns the positioning, 21 channel records, official reference URLs, known blockers and existing-submission status. `adapters/` contains the native n8n, Zapier, WordPress, Workspace and Chrome source. Make components and MCP manifests are generated by `scripts/build-distribution.mjs`. `lib/partner-client.cjs` implements the restricted Partner API contract. `tests/` tests local contracts and mocked hosts; it is not live acceptance.

## Build and verify

Run `node scripts/verify-distribution.mjs` from the repository root. The generated `dist/distribution/START_HERE.md` indexes every pack. `VERIFY.cmd` and `VERIFY.sh` provide launchers. Install native platform dependencies and retain resolved lockfiles before release; preparation had no working npm download access.

Existing Claude/ChatGPT/Cursor/Grok release contents stay unchanged. Their packs contain revised listing copy for updating the original records, not duplicate publication. EmDash PR #12 remains separate.

## Honest readiness levels

- MCP/directories: native configs or structured nomination/listing material, followed by platform-specific validation and OAuth acceptance.
- n8n/Zapier/Make: explicit API-approved operations and secure upload handoff, not fabricated webhooks or automatic evidence ingestion.
- WordPress: site-administrator integration, not a public visitor form.
- Workspace: Drive sidebar; no automatic Drive-content access. Review the visible key-entry/per-user storage pilot flow before public release.
- Chrome: explicit local evidence-note capture and manual website handoff, not authenticated in-browser analysis.
- Microsoft: templates, real-tool discovery and required-value finalizer; certification is not complete.
- HubSpot: dependency handoff for existing backend PR #687; deal card/writeback remain unfinished.

## Validation preservation

The former public-package validator is retained byte-for-byte at `.github/validate-legacy-tree.mjs`. The entry script scans the entire source and runs those same legacy checks against a temporary legacy-package view. It does not remove identity, version, logo, credential or archive-parity checks. New CI adds local tests plus separately reported n8n/Zapier native checks; nothing auto-publishes.

No production change, marketplace submission, merge or deployment is authorized by these preparation files.
