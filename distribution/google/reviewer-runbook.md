# Google review demonstration

This is a proposed demonstration targeting the prepared 0.9.2 contract at canonical source pin `00682b0179824fcf182856713de5864b54b140c2`. Published public plugin source is 0.9.1. Source preparation does not establish that the runtime has deployed this contract or that a Google host run has passed. Confirm the live schema and execute with a dedicated test account and synthetic commercial evidence. No credentials or real customer files belong in this repository.

1. In [Gemini Developer Mode](https://gemini.google.com/devmode), connect the public endpoint and complete Ultiwrite OAuth. Ask `@Ultiwrite which account is connected?` Verify the identity returned by `ultiwrite_account_get`.
2. Ask `@Ultiwrite what evidence can I submit for an acquisition investigation?` Verify current capabilities and limitations returned by `ultiwrite_capabilities_get`.
3. Say `I authorize submitting this synthetic acquisition package to Ultiwrite using this account's existing allowance. Leave Document Forensics at the service default.` Use the exact input schema advertised by the server. If Gemini cannot forward file bytes in a supported format, call `ultiwrite_evidence_submit` with `{files: [], caseId: null, handoffId: null, documentForensics: null}`; use the returned secure upload link. If supported original file objects are available, forward those objects unchanged in `files`, preserving the other required fields and the authorized Document Forensics choice.
4. Retain the exact returned `handoffId`. Upload only the synthetic package. After browser upload confirms receipt, call `ultiwrite_evidence_submit` with `{files: [], caseId: null, handoffId: returnedHandoffId, documentForensics: null}` to recover that exact saved case. Do not guess it from the newest case or ask the reviewer to copy identifiers. Advance a server-requested continuation only with `{files: [], caseId: returnedCaseId, handoffId: null, documentForensics: null}`. Do not claim that link creation or completed upload means the investigation is finished.
5. Ask `What is the status of the investigation I just submitted?` Read `ultiwrite_case_status` for that specific case. Surface any user action required.
6. After publication, ask `Use Ultiwrite to show the evidence-backed findings and remaining questions in that report.` Read `ultiwrite_findings_get` and `ultiwrite_coherence_get`, preserving pagination, uncertainty and evidence citations.
7. Ask for the report. Use `ultiwrite_report_export`; open the returned link while signed in to the same Ultiwrite account. Confirm an actual report/download opens.
8. Revoke the test grant and reconnect. Confirm protected tools reject the revoked grant and the intended account appears after reconnecting. Check a read-only grant cannot submit evidence.

Record host version/date, case/report IDs, scope selection, actual states and the export result in the private review record. Use only redacted or synthetic screenshots in a submission.

Google explains the live debug environment in its [Developer Mode overview](https://developers.google.com/connected-apps/mcp/dev-mode). Its [registration guide](https://developers.google.com/connected-apps/gpc/perform-the-steps) requires a usable seeded reviewer account for delegated-auth apps. Provide review credentials directly through the authorized review process, never in a public ZIP.
